# Airline Booking & Operations System

Дипломный проект: Система бронирования авиабилетов и управления рейсами

---

## 📋 О проекте

**Airline Booking & Operations System** — полнофункциональная система бронирования авиабилетов с разделением ролей пользователей (пассажиры и персонал авиакомпании).

Система реализована по архитектуре **клиент-сервер**:
- **Backend (REST API):** FastAPI с JWT-авторизацией, бизнес-логикой бронирований и управления рейсами
- **Frontend (Mobile):** Flutter-приложение для Android с Material Design интерфейсом

Проект демонстрирует применение современных технологий разработки, паттернов проектирования (Repository, Service Layer) и best practices в области веб-разработки и мобильной разработки.

## 🛠 Стек технологий

### Backend
- **Python 3.10+** — язык программирования
- **FastAPI** — современный асинхронный веб-фреймворк для REST API
- **SQLAlchemy 2.0** — ORM для работы с базой данных
- **SQLite** — реляционная СУБД (легко мигрируется на PostgreSQL)
- **JWT (python-jose)** — токен-авторизация
- **Pydantic** — валидация данных
- **Passlib (bcrypt)** — хеширование паролей
- **Uvicorn** — ASGI сервер

### Frontend
- **Flutter 3.x** — кроссплатформенный фреймворк (Dart)
- **Material Design 3** — дизайн-система Google
- **http** — HTTP клиент для взаимодействия с API
- **flutter_secure_storage** — безопасное хранение JWT токенов
- **qr_flutter** — генерация QR-кодов для посадочных талонов
- **google_fonts** — типографика (Montserrat)

## ✨ Ключевой функционал

### Для пассажиров:
- ✅ **Регистрация и авторизация** с JWT токенами
- ✅ **Поиск рейсов** по маршруту и дате вылета
- ✅ **Визуальная карта мест** с категориями (стандарт, extra legroom)
- ✅ **Логика Hold (10 минут)** — автоматическое удержание мест с таймером обратного отсчета
- ✅ **Имитация оплаты** — подтверждение бронирования
- ✅ **Генерация посадочных талонов** с QR-кодами
- ✅ **Регистрация на рейс** (check-in) в окне 24ч - 1ч до вылета
- ✅ **Уведомления о рейсах** — автоматические оповещения об объявлениях
- ✅ **Управление профилем** (ФИО, паспортные данные)

### Для персонала авиакомпании:
- ✅ **Управление рейсами** (создание, редактирование, изменение статуса)
- ✅ **Управление самолётами** (добавление, редактирование парка воздушных судов)
- ✅ **Публикация объявлений** по рейсам (задержка, смена гейта, отмена)
- ✅ **Просмотр всех бронирований** с фильтрацией по статусам
- ✅ **Админ-панель** с полным доступом к системе

### Технические особенности:
- 🔒 **Предотвращение двойного бронирования** — UNIQUE constraints на уровне БД
- 🔄 **Фоновая очистка** истекших Hold-мест (каждые 60 секунд)
- 🎯 **Идемпотентность операций** — безопасная повторная обработка платежей
- 📱 **Адаптивный UI** — оптимизация под разные размеры экранов
- 🌍 **Timezone-aware** — корректная работа с часовыми поясами (Бишкек UTC+6)

## 🚀 Инструкция по запуску

### Требования:
- Python 3.10 или выше
- Flutter SDK 3.x
- Android SDK (для запуска мобильного приложения)

---

### Backend (FastAPI)

#### 1. Создание виртуального окружения

```bash
cd backend
python -m venv .venv
```

#### 2. Активация окружения

**Windows (PowerShell):**
```powershell
.venv\Scripts\Activate.ps1
```

**Linux/macOS:**
```bash
source .venv/bin/activate
```

#### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

#### 4. Запуск сервера

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

**Важно:** База данных инициализируется автоматически при первом запуске!  
Система создаёт:
- Тестовых пользователей (staff и passenger)
- Аэропорты Кыргызстана и России (5 шт.)
- Самолёт Boeing 737-800 (60 мест)
- Автоматически генерируемые места с категориями

Сервер будет доступен по адресу: **http://localhost:8000**

---

### Frontend (Flutter)

#### 1. Установка зависимостей

```bash
cd frontend
flutter pub get
```

#### 2. Настройка API endpoint

**Для эмулятора Android:**  
По умолчанию используется `http://10.0.2.2:8000/api/v1`

**Для физического устройства:**  
Узнайте IP-адрес вашего компьютера и запустите:

```bash
flutter run -d <DEVICE_ID> --dart-define=API_BASE_URL=http://<YOUR_IP>:8000/api/v1
```

Пример:
```bash
flutter run -d emulator-5554 --dart-define=API_BASE_URL=http://192.168.1.100:8000/api/v1
```

#### 3. Запуск приложения

**На эмуляторе:**
```bash
flutter run
```

**На физическом устройстве:**
```bash
flutter devices  # Найти DEVICE_ID
flutter run -d <DEVICE_ID>
```

## 📚 API Документация

Интерактивная документация API доступна после запуска backend:

- **Swagger UI:** [http://localhost:8000/docs](http://localhost:8000/docs)
- **ReDoc:** [http://localhost:8000/redoc](http://localhost:8000/redoc)

### Основные эндпоинты:

#### Публичные (без авторизации):
- `POST /api/v1/auth/register` — регистрация пассажира
- `POST /api/v1/auth/login` — вход (получение JWT токена)
- `GET /api/v1/flights` — поиск рейсов
- `GET /api/v1/flights/{id}/seats` — карта мест рейса

#### Для авторизованных пассажиров:
- `POST /api/v1/bookings` — создание бронирования
- `POST /api/v1/payments/process` — оплата бронирования
- `POST /api/v1/checkin` — регистрация на рейс
- `GET /api/v1/checkin/ticket/{number}` — получение посадочного талона

#### Для персонала:
- `POST /api/v1/staff/flights` — создание рейса
- `POST /api/v1/staff/announcements` — публикация объявления
- `GET /api/v1/staff/bookings` — просмотр всех бронирований

## ⚠️ Технический долг и ограничения MVP

Проект реализован как **Minimum Viable Product (MVP)** для демонстрации функциональности. В текущей версии присутствуют следующие упрощения:

### База данных:
- **SQLite** используется для удобства разработки и демонстрации
- ✅ **Готовность к миграции:** Архитектура позволяет легко переключиться на PostgreSQL для production
- ⚠️ **Без миграций:** Изменения схемы требуют пересоздания БД (Alembic запланирован в следующей итерации)

### Безопасность:
- ⚠️ `SECRET_KEY` и другие конфигурационные параметры находятся в коде для упрощения проверки проекта
- ✅ **Production-ready:** В реальной среде все секреты переносятся в `.env` файл (шаблон `.env.example` готов)

### Оплата:
- ⚠️ **Mock Payment Provider:** Все платежи автоматически проходят успешно (имитация)
- ✅ **Архитектура готова:** Интерфейс `PaymentService` позволяет легко интегрировать реальные платёжные шлюзы (Stripe, Kaspi, Halyk Bank)

### Планы по улучшению:
1. Миграция на PostgreSQL + Alembic
2. Вынос секретов в переменные окружения
3. Интеграция с реальными платёжными системами
4. Email/SMS уведомления
5. Unit и интеграционные тесты (pytest, flutter_test)

## 📊 База данных

Схема включает **13 таблиц** с полными связями:

- **users** — пользователи (роли: PASSENGER / STAFF)
- **passenger_profiles** — профили пассажиров (обязательны для бронирования)
- **airports** — аэропорты
- **airplanes** — парк самолётов
- **flights** — рейсы (статусы: SCHEDULED → BOARDING → DEPARTED → LANDED)
- **bookings** — бронирования (PNR, статусы: CREATED → CONFIRMED → CANCELLED)
- **tickets** — билеты (UNIQUE constraint на flight_id + seat_number)
- **seat_holds** — временное удержание мест (10 мин, UNIQUE constraint)
- **payments** — платежи (идемпотентность через external_payment_id)
- **checkins** — регистрации на рейс
- **announcements** — объявления рейсов
- **notifications** — уведомления пассажиров
- **booking_passengers** — связь бронирований и пассажиров (many-to-many)
